#　機能：注文機能

## テスト対象API

-'POST/api/orders'

## テストデータ準備方針：

- テストの独立性を保つため、各テストケース実行前にデータベースをクリーンな状態にし、テストケースごとに必要な商品データを投入することを想定します。
- 以下では、テストデータとして投入される商品情報を `Product(ID, Name, Price, Desc, Stock, ImageUrl, IsRecommended)` の形式で記述します。

## テストシナリオ

### No. 3-1

- テストケース名:  会員がカートに1種類の商品を入れて注文する（合計4999円）
- 前提条件
  - テスト商品として以下の商品がDBに登録されていること
  - Product(1, "テスト商品A", 4999, "テスト用の商品Aです", 10, "/images/wooden-coaster.png", false)
  - テスト用の会員情報がDBに登録されていること（例: User(ID: 101, Username: "testuser", Password: "password")）

- 手順:
1. 会員認証: テスト用の会員(User(ID: 101))としてシステムにログインし、認証トークン（JWTなど）またはセッションIDを取得する。

   - HTTPリクエスト☆: POST /api/login (リクエストボディ: {"username": "testuser", "password": "password"})
   - 期待されるレスポンス: 認証成功を示すステータスコード（例: 200 OK）と、後続のリクエストで使用する認証情報（トークン、セッションクッキーなど）。
2. カートへの商品追加: 取得した認証情報を使用して、商品ID: 1 の商品を1点、カートに追加するリクエストを送信する。
   - HTTPリクエスト: POST /api/cart/items
   - リクエストヘッダ: Authorization: Bearer [取得した認証トークン] または適切なセッション情報
   - リクエストボディ: {"productId": 1, "quantity": 1}
   - 期待されるレスポンス: 200 OK または 201 Created。セッション内にカート情報が保持されていることを確認（テストツールによっては直接セッション内容を確認できないため、次の注文で検証）。
3. 注文確定: 取得した認証情報を使用して、HTTP POSTリクエストを /api/orders エンドポイントに送信し、注文を確定する。
   - HTTPリクエスト: POST /api/orders
   - リクエストヘッダ: Authorization: Bearer [取得した認証トークン] または適切なセッション情報
   - リクエストボディ: {"shippingAddress": "東京都品川区", "paymentMethod": "代金引換"}
4. -> OrderController
5. -> CartService
6. -> OrderService
7. -> (ProductRepository, OrderRepository, ProductRepository[update], CartService)
8.  -> DB, Session

- 入力データ:
    - ログイン時: { "username": "testuser", "password": "password" }
    - カート追加時: { "productId": 1, "quantity": 1 }
    - 注文確定時: { "shippingAddress": "東京都品川区", "paymentMethod": "代金引換" }

- 期待結果:
  1. 注文が成功し、注文IDと注文日時を含むJSONが返却される (201 Created)。
     - orderId (注文ID)
     - orderDate (注文日時)
     - shippingFee: 500
     - totalPrice: 4999
     - totalPrice + shippingFee: 5499 (商品合計4999円 + 送料500円)
  
  2. DBに注文情報が登録され、対象商品の在庫が更新されている。
    - Order テーブルに新規レコードが登録され、customer_id がNULLであること。
    - OrderDetail テーブルに、注文された商品（ID: 1, 数量: 1, 単価: 4999）のレコードが登録されていること。
    - Product テーブルのProduct ID: 1 の在庫が 10 から 9 に減少していること。
  
  3. セッションからカートがクリアされる。
  4. 送料は500円。
  5. CustomerId が＊＊＊であること。
