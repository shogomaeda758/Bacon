# 機能：注文機能

## テスト対象API

- `POST /api/orders` （このテストケースでは `/api/orders/confirm` を使用）

## テストデータ準備方針：

- テストの独立性を保つため、各テストケース実行前にデータベースをクリーンな状態にし、テストケースごとに必要な商品データを投入することを想定します。
- 以下では、テストデータとして投入される商品情報を `Product(ID, Name, Price, Desc, Stock, ImageUrl, IsRecommended)` の形式で記述します。

## テストシナリオ

### No. 3-20

- テストケース名: 注文（異常系 - (模擬) 注文DB保存時にエラー発生）
- 前提条件:
    - DBにテスト商品として以下の商品が登録されていること:
        - `Product(1, "シンプルデスクオーガナイザー", 3500, "机の上をすっきり整理できる木製オーガナイザー。", 20, "/images/desk-organizer.png", true)`
    - セッションに以下のカート情報が存在すること:
        - `Cart(items={"1": CartItem(productId=1, quantity=1, subtotal=3500)})`
    - フロントエンドのフォームは適切に記入されており、バリデーションを通過する状態であること。
    - **(テスト実装上の工夫)**: `OrderRepository.save` メソッドが呼び出された際に、意図的に例外（例: `RuntimeException("DB save error")`）をスローするようにテスト用実装で設定する。

- 手順:
    1. フロントエンドで注文フォームに顧客情報と決済方法を入力する。
        - **入力例**: 名前: "顧客 太郎", メール: "test-member-a@example.com", 住所: "東京都品川区", 電話番号: "0123456789", 決済方法: "銀行振込"
    2. 「注文内容を確認する」ボタン（`#submit-order-form-and-show-confirmation`）をクリックする。
    3. フロントエンドで顧客情報と決済方法のバリデーションが成功し、`currentOrderData` に情報が格納される。
    4. カート情報の取得API (`GET /cart`) が呼び出され、カート内容が `currentOrderData.items` に格納される。
    5. 注文確認モーダルが表示される。
    6. 「注文を確定する」ボタン（`#final-confirm-order-btn`）をクリックする。
    7. HTTP POSTリクエストを `/api/orders/confirm` エンドポイントに送信する。
        - **HTTPリクエスト**: `POST /api/orders/confirm`
        - **リクエストボディ**: `currentOrderData` の内容
        - **セッション**: 上記前提条件のカート情報
    8. -> OrderController
    9. OrderControllerがCartService.getCartFromSession(session)を呼び出し、カート情報を取得する。
    10. OrderControllerがOrderService.placeOrder(カート情報, 注文リクエスト)を呼び出す。
    11. OrderServiceがカート内の商品の在庫確認を行い、問題ないことを確認する。
    12. OrderServiceが注文情報を構築し、OrderRepository.saveを呼び出す。
    13. -> OrderRepository (意図的に例外をスローするように設定されている)
    14. OrderRepository.saveが例外(`RuntimeException("DB save error")`)をスローし、OrderServiceに返却される。
    15. OrderServiceで捕捉されない例外がOrderControllerに伝播する。
    16. OrderControllerのtry-catchブロックで`Exception`（ここでは`RuntimeException`）を捕捉し、エラーレスポンスを生成する。
    17. HTTPレスポンスを受信する。
    18. フロントエンドでエラーメッセージを表示する（`handleError`関数経由でアラートなど）。

- 入力データ (APIリクエストとして送信されるデータ):
    ```json
    {
      "customerInfo": {
        "name": "顧客 太郎",
        "email": "test-member-a@example.com",
        "address": "東京都品川区",
        "phoneNumber": "0123456789"
      },
      "paymentMethod": "銀行振込",
      "items": [
        {
          "productId": 1,
          "name": "シンプルデスクオーガナイザー",
          "price": 3500,
          "quantity": 1,
          "subtotal": 3500
        }
      ],
      "totalPrice": 3500,
      "shippingFee": 500, 
      "grandTotal": 3500 
    }
    ```

- 期待結果:
    1. HTTPステータスコードが **`500 Internal Server Error`** であること（`OrderService` 内で発生した`RuntimeException`が`OrderController` の`catch (Exception e)`ブロックで処理されるため）。
    2. レスポンスボディがJSON形式であり、エラーメッセージ **`"注文確定中に予期せぬエラーが発生しました。"`** を含む `OrderResponse` であること。
    3. DB状態変化: `orders`, `order_details`, `products` テーブルに変化がないこと（`@Transactional` によりロールバックされる）。
    4. セッション状態変化: セッションの `cart` 属性がクリアされずに残っていること。
    5. `OrderService.placeOrder` 内で `orderRepository.save` が呼び出され、そこで例外が発生すること。`CartService.clearCart` は呼び出されないこと。
    6. **フロントエンドの挙動:**
        * 注文確認モーダルが閉じられ、エラーメッセージのアラートが表示されること（`handleError`関数経由）。
        * カートの内容はクリアされず、注文フォームもリセットされないこと。
