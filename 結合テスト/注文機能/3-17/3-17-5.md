# 機能：注文機能

## テスト対象API

- `POST /api/orders`

## テストデータ準備方針：

- テストの独立性を保つため、各テストケース実行前にデータベースをクリーンな状態にし、テストケースごとに必要な商品データを投入することを想定します。
- 以下では、テストデータとして投入される商品情報を `Product(ID, Name, Price, Desc, Stock, ImageUrl, IsRecommended)` の形式で記述します。

## テストシナリオ

### No. 3-17-5

- テストケース名: 注文（異常系 - 顧客情報不足、支払い方法が空）
- 前提条件:
    - DBにテスト商品として以下の商品が登録されていること:
        - `Product(1, "シンプルデスクオーガナイザー", 3500, "机の上をすっきり整理できる木製オーガナイザー。", 20, "/images/desk-organizer.png", true)`
    - セッションに以下のカート情報が存在すること:
        - `Cart(items={"1": CartItem(productId=1, quantity=1, subtotal=3500)})`

- 手順:
    1. フロントエンドで注文フォームに顧客情報を入力する際、**支払い方法を空にする**。
        - **入力例**: 名前: "顧客　太郎", メール: "test-member-a@example.com", 住所: "東京都品川区", 電話番号: "0123456789", 決済方法: ""
    2. 「注文内容を確認する」ボタン（`#submit-order-form-and-show-confirmation`）をクリックする。
    3. フロントエンドの `submitOrderFormAndShowConfirmation` 関数内で `form.checkValidity()` が実行され、名前フィールドのバリデーションエラーが検出される。
    4. `form.classList.add('was-validated')` が追加され、`form.querySelector(':invalid')?.focus()` で不正な入力フィールドにフォーカスが当たる。
    5. `return` で関数が終了し、APIリクエストは送信されない。

- 入力データ (フロントエンドでの入力):
    {
"customerInfo": {
"name": "顧客　太郎",
"email": "test-member-a@example.com",
"address": "東京都品川区",
"phoneNumber": "0123456789"
},
"paymentMethod": "",
"items": [
{
"productId": 1,
"name": "シンプルデスクオーガナイザー",
"price": 3500,
"quantity": 1,
"subtotal": 3500
}
],
"totalPrice": 3500,
"shippingFee": 500,
"grandTotal": 4000
}

- 期待結果:
  1. HTTPステータスコードが `400 Bad Request` であること。
  2. レスポンスボディに `customerInfo.email` に関するバリデーションエラーメッセージ（支払い方法は必須です。）を含むJSONが返却されること。
  3. `OrderService` は呼び出されないこと。
  4. DB状態変化: なし。
  5. セッション状態変化: なし。
