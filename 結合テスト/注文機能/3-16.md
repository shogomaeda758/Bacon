# 機能：注文機能

## テスト対象API

- `POST /api/orders`

## テストデータ準備方針：

- テストの独立性を保つため、各テストケース実行前にデータベースをクリーンな状態にし、テストケースごとに必要な商品データを投入することを想定します。
- 以下では、テストデータとして投入される商品情報を `Product(ID, Name, Price, Desc, Stock, ImageUrl, IsRecommended)` の形式で記述します。

## テストシナリオ

### No. 3-16

- テストケース名: 注文（異常系 - カート内の商品がDBに存在しない）
- 前提条件:
    - **DBには以下の商品が存在しないこと:**
        - `productId = 999` の商品
    - セッションに以下のカート情報が存在すること:
        - `Cart(items={"999": CartItem(productId=999, productName="不明な商品", price=1000, quantity=1, subtotal=1000)}, totalQuantity=1, totalPrice=1000)` （存在しない商品ID:999 がカートに入っている）
    - フロントエンドのフォームは適切に記入されており、バリデーションを通過する状態であること。

- 手順:
    1. フロントエンドで注文フォームに顧客情報と決済方法を入力する。
        - **入力例**: 名前: "顧客 太郎", メール: "taro@test.com", 住所: "東京都新宿区テスト1-2", 電話番号: "03-9876-5432", 決済方法: "クレジットカード"
    2. 「注文内容を確認する」ボタン（`#submit-order-form-and-show-confirmation`）をクリックする。
    3. フロントエンドで顧客情報と決済方法のバリデーションが成功し、`currentOrderData` に情報が格納される。
    4. カート情報の取得API (`GET /cart`) が呼び出され、カート内容が `currentOrderData.items` に格納される。
    5. 注文確認モーダルが表示される。
    6. 「注文を確定する」ボタン（`#final-confirm-order-btn`）をクリックする。
    7. HTTP POSTリクエストを `/api/orders/confirm` エンドポイントに送信する。
        - **HTTPリクエスト**: `POST /api/orders/confirm`
        - **リクエストボディ**: `currentOrderData` の内容（顧客情報、決済方法、カートアイテム、合計金額など）
        - **セッション**: 上記前提条件のカート情報
    8. -> OrderController
    9. OrderControllerがCartService.getCartFromSession(session)を呼び出す。
    10. CartServiceがセッションからカート情報を取得し、OrderControllerに返却する。
    11. OrderControllerがOrderService.placeOrder(カート情報, 注文リクエスト)を呼び出す。
    12. OrderServiceがカート内の商品ID 999 についてProductRepository.findById(999)を呼び出し、DBから商品情報を検索する。
    13. -> DB (商品情報検索)
    14. DB -> ProductRepository (商品が見つからないため`Optional.empty()`を返却)
    15. ProductRepositoryから返却された`Optional.empty()`を受けて、OrderServiceが`IllegalArgumentException`をスローする。
    16. OrderControllerのtry-catchブロックで`IllegalArgumentException`を捕捉し、エラーレスポンスを生成する。
    17. HTTPレスポンスを受信する。
    18. フロントエンドでエラーメッセージを表示する（`handleError`関数経由でアラートなど）。

- 入力データ (APIリクエストとして送信されるデータ):
    ```json
    {
      "customerInfo": {
        "name": "顧客 太郎",
        "email": "taro@test.com",
        "address": "東京都新宿区テスト1-2",
        "phoneNumber": "03-9876-5432"
      },
      "paymentMethod": "クレジットカード",
      "items": [
        {
          "productId": 999,
          "productName": "不明な商品",
          "price": 1000,
          "quantity": 1,
          "subtotal": 1000
        }
      ],
      "totalPrice": 1000,
      "shippingFee": 0, // 仮定
      "grandTotal": 1000 // 仮定
    }
    ```

- 期待結果:
    1. HTTPステータスコードが **`400 Bad Request`** であること（`OrderService` 内で `IllegalArgumentException` がスローされ、`OrderController` の`catch (IllegalArgumentException e)`ブロックで処理されるため）。
    2. レスポンスボディがJSON形式であり、エラーメッセージ **`"商品が見つかりません: 不明な商品"`** を含む `OrderResponse` であること。
    3. DB状態変化: `orders`, `order_details`, `products` テーブルに変化がないこと（`@Transactional` によりロールバックされる）。
    4. セッション状態変化: セッションの `cart` 属性がクリアされずに残っていること。
    5. `OrderService.placeOrder` が呼び出されるが、`productRepository.findById(999)` が `Optional.empty()` を返し、`IllegalArgumentException`がスローされること。
    6. **フロントエンドの挙動:**
        * 注文確認モーダルが閉じられ、エラーメッセージのアラートが表示されること（`handleError`関数経由）。
        * カートの内容はクリアされず、注文フォームもリセットされないこと。
