# 機能：注文機能

## テスト対象API

- `POST /api/orders` （このテストケースでは `/api/orders/confirm` を使用）

## テストデータ準備方針：

- テストの独立性を保つため、各テストケース実行前にデータベースをクリーンな状態にし、テストケースごとに必要な商品データを投入することを想定します。
- 以下では、テストデータとして投入される商品情報を `Product(ID, Name, Price, Desc, Stock, ImageUrl, IsRecommended)` の形式で記述します。

## テストシナリオ

### No. 3-19

- テストケース名: 注文（異常系 - リクエストボディが空、または不正なJSON）
- 前提条件:
    - DBにテスト商品として以下の商品が登録されていること:
        - `Product(1, "シンプルデスクオーガナイザー", 3500, "机の上をすっきり整理できる木製オーガナイザー。", 20, "/images/desk-organizer.png", true)`
    - セッションに以下のカート情報が存在すること:
        - `Cart(items={"1": CartItem(productId=1, quantity=1, subtotal=3500)})`
    - フロントエンドのフォームは適切に記入されており、バリデーションを通過する状態であること。
    - **(テスト実装上の工夫)**: テストハーネス/ツールで、`submitOrderFormAndShowConfirmation` 成功後の `/api/order/confirm` へのリクエストボディを意図的に空にするか、不正なJSONに加工して送信する。

- 手順:
    1. フロントエンドで注文フォームに顧客情報と決済方法を入力する。
        - **入力例**: 名前: "顧客 太郎", メール: "test-member-a@example.com", 住所: "東京都品川区", 電話番号: "0123456789", 決済方法: "銀行振込"
    2. 「注文内容を確認する」ボタン（`#submit-order-form-and-show-confirmation`）をクリックする。
    3. フロントエンドで顧客情報と決済方法のバリデーションが成功し、`currentOrderData` に情報が格納される。
    4. カート情報の取得API (`GET /cart`) が呼び出され、カート内容が `currentOrderData.items` に格納される。
    5. 注文確認モーダルが表示される。
    6. 「注文を確定する」ボタン（`#final-confirm-order-btn`）をクリックする。
    7. HTTP POSTリクエストを `/api/orders/confirm` エンドポイントに送信する。
        - **HTTPリクエスト**: `POST /api/orders/confirm`
        - **リクエストボディ**: **以下のいずれかをテストする**
            - 空のリクエストボディ
            - JSONとして不正な形式の文字列 (例: `{ "customerInfo": }` や `{"invalid_json"`)
            - 完全な非JSON文字列 (例: `not a json string`)
        - **セッション**: 上記前提条件のカート情報
    8. Spring MVCのメッセージコンバーターがリクエストボディの解析を試みる。
    9. リクエストボディが不正な形式であるため、`HttpMessageNotReadableException`が発生する。
    10. OrderControllerの`@ExceptionHandler(HttpMessageNotReadableException.class)`で定義された`handleHttpMessageNotReadableException`メソッドが呼び出され、エラーレスポンスを生成する。
    11. HTTPレスポンスを受信する。
    12. フロントエンドでエラーメッセージを表示する（`handleError`関数経由でアラートなど）。

- 入力データ (APIリクエストとして送信されるデータ):
    - 空のリクエストボディ
    - または、JSONとして不正な形式の文字列 (例: `{ "customerInfo": }` や `{"invalid_json"`)
    - または、完全な非JSON文字列 (例: `not a json string`)

- 期待結果:
    1. HTTPステータスコードが **`400 Bad Request`** であること（`HttpMessageNotReadableException` が発生し、`handleHttpMessageNotReadableException` メソッドで処理されるため）。
    2. レスポンスボディがJSON形式であり、エラーメッセージ **`"リクエストボディのJSON形式が不正です。"`** を含む `OrderResponse` であること。
    3. `OrderController.placeOrder` メソッドが呼び出される前に `HttpMessageNotReadableException` が発生し、`@ExceptionHandler(HttpMessageNotReadableException.class)` で処理されること。
    4. DB状態変化: なし。
    5. セッション状態変化: なし。
    6. **フロントエンドの挙動:**
        * 注文確認モーダルが閉じられ、エラーメッセージのアラートが表示されること（`handleError`関数経由）。
        * カートの内容はクリアされず、注文フォームもリセットされないこと。
