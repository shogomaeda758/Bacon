# 機能：注文機能

## テスト対象API

- `POST /api/orders` （このテストケースでは `/api/orders/confirm` を使用）
- `DELETE /api/cart`

## テストデータ準備方針：

- テストの独立性を保つため、各テストケース実行前にデータベースをクリーンな状態にし、テストケースごとに必要な商品データを投入することを想定します。
- 以下では、テストデータとして投入される商品情報を `Product(ID, Name, Price, Desc, Stock, ImageUrl, IsRecommended)` の形式で記述します。

## テストシナリオ

### No. 3-22

- テストケース名: 注文（異常系 - (模擬) カートクリア時にエラー発生）
- 前提条件:
    - DBにテスト商品として以下の商品が登録されていること:
        - `Product(1, "シンプルデスクオーガナイザー", 3500, "机の上をすっきり整理できる木製オーガナイザー。", 20, "/images/desk-organizer.png", true)`
    - セッションに以下のカート情報が存在すること:
        - `Cart(items={"1": CartItem(productId=1, quantity=1, subtotal=3500)})`
    - フロントエンドのフォームは適切に記入されており、バリデーションを通過する状態であること。
    - **(テスト実装上の工夫)**: `/api/cart` への DELETE リクエストが呼び出された際に、意図的にエラーレスポンス（例: ステータスコード `500`）を返すようにモックまたはテスト用実装で設定する。

- 手順:
    1. フロントエンドで注文フォームに顧客情報と決済方法を入力する。
        - **入力例**: 名前: "顧客 太郎", メール: "taro@test.com", 住所: "東京都新宿区テスト1-2", 電話番号: "03-9876-5432", 決済方法: "クレジットカード"
    2. 「注文内容を確認する」ボタン（`#submit-order-form-and-show-confirmation`）をクリックする。
    3. フロントエンドで顧客情報と決済方法のバリデーションが成功し、`currentOrderData` に情報が格納される。
    4. カート情報の取得API (`GET /cart`) が呼び出され、カート内容が `currentOrderData.items` に格納される。
    5. 注文確認モーダルが表示される。
    6. 「注文を確定する」ボタン（`#final-confirm-order-btn`）をクリックする。
    7. HTTP POSTリクエストを `/api/orders/confirm` エンドポイントに送信する。
        - **HTTPリクエスト**: `POST /api/orders/confirm`
        - **リクエストボディ**: `currentOrderData` の内容
        - **セッション**: 上記前提条件のカート情報
    8. -> OrderController
    9. OrderControllerがOrderService.placeOrder(カート情報, 注文リクエスト)を呼び出す。
    10. OrderServiceが正常に注文処理（在庫確認、注文DB保存、在庫更新）を完了し、OrderResponseをOrderControllerに返却する。
    11. OrderControllerに制御が戻り、正常レスポンスが返される。
    12. フロントエンドの `confirmOrder` 関数内で、次に `/api/cart` (DELETE) へのリクエストが送信される。
    13. -> `/api/cart` (DELETE) エンドポイント (意図的にエラーレスポンスを返すように設定されている)
    14. フロントエンドが `/api/cart` からのエラーレスポンスを受け取る。
    15. フロントエンドの `confirmOrder` 関数内でカートクリアに失敗した旨のアラートを表示し、注文完了モーダルを表示する。

- 入力データ (APIリクエストとして送信されるデータ):
    ```json
    {
      "customerInfo": {
        "name": "顧客 太郎",
        "email": "taro@test.com",
        "address": "東京都新宿区テスト1-2",
        "phoneNumber": "03-9876-5432"
      },
      "paymentMethod": "クレジットカード",
      "items": [
        {
          "productId": 1,
          "name": "シンプルデスクオーガナイザー",
          "price": 3500,
          "quantity": 1,
          "subtotal": 3500
        }
      ],
      "totalPrice": 3500,
      "shippingFee": 0, // 仮定
      "grandTotal": 3500 // 仮定
    }
    ```

- 期待結果:
    1. `/api/orders/confirm` へのHTTPリクエストは **`200 OK`** で成功すること。
    2. `/api/cart` へのHTTP DELETEリクエストは **`500 Internal Server Error`** またはその他のエラー（例: `4xx`）を返すこと。
    3. DB状態変化: `orders`, `order_details` テーブルに新規注文が登録され、`products` テーブルの在庫が減少していること（**注文処理自体は成功し、カートクリアのエラーはロールバックされないため**）。
    4. セッション状態変化: カートクリアに失敗するため、セッションの `cart` 属性は残ったままになること。
    5. **フロントエンドの挙動:**
        * 「注文を確定する」ボタンクリック後、`handleError`関数経由で**「注文は正常に完了しましたが、カートのクリア中に問題が発生しました。」というアラートが表示される**こと。
        * 注文完了モーダルが正常に表示され、注文番号や合計金額などの情報が表示されること。
        * カートバッジは0に更新されないこと（カートクリアAPIの失敗のため）。
        * 注文フォームはリセットされること。
        * `currentOrderData` はリセットされること。
