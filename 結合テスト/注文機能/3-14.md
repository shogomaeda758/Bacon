## テスト対象API

- `POST /api/orders`

## テストデータ準備方針：

- テストの独立性を保つため、各テストケース実行前にデータベースをクリーンな状態にし、テストケースごとに必要な商品データを投入することを想定します。
- 以下では、テストデータとして投入される商品情報を `Product(ID, Name, Price, Desc, Stock, ImageUrl, IsRecommended)` の形式で記述します。

## テストシナリオ

### No. 3-14

- テストケース名: 注文（異常系 - カートが空の状態で注文）
- 前提条件:
    - セッションにカート情報が存在しない、またはカートオブジェクトは存在するが `cart.getItems()` が空である。
    - **DBに以下の商品が登録されていること（このテストケースでは直接使用しないが、システム全体の初期状態として想定）:**
        - `Product(1, "シンプルデスクオーガナイザー", 3500, "机の上をすっきり整理できる木製オーガナイザー。ペン、メモ、スマートフォンなどを収納できます。", 20, "/images/desk-organizer.png", true)`
        - `Product(2, "アロマディフューザー（ウッド）", 4200, "天然木を使用したシンプルなデザインのアロマディフューザー。LEDライト付き。", 15, "/images/aroma-diffuser.png", true)`
    - **フロントエンドの挙動として、カートが空の場合に注文ボタンを押してもバックエンドにリクエストが送信されないことを考慮する。そのため、このテストはバックエンドのAPIテストとして実施されることを想定。**

- 手順:
    1. HTTP POSTリクエストを `/api/orders` エンドポイントに送信する。
        - **HTTPリクエスト**: `POST /api/orders`
        - **リクエストボディ**:
            ```json
            {
              "customerInfo": {
                "name": "顧客 太郎",
                "email": "taro@test.com",
                "address": "東京都新宿区テスト1-2",
                "phoneNumber": "03-9876-5432"
              },
              "paymentMethod": "クレジットカード"
            }
            ```
        - **セッション**: 空
    2. -> OrderController
    3. OrderControllerがCartService.getCartFromSession(session)を呼び出す。
    4. CartServiceがセッションからカート情報を取得し、空であることをOrderControllerに返却する。
    5. OrderControllerがカートが空であると判断し、エラーレスポンスを生成する。
    6. HTTPレスポンスを受信する。

- 入力データ:
    ```json
    {
      "customerInfo": {
        "name": "顧客 太郎",
        "email": "taro@test.com",
        "address": "東京都新宿区テスト1-2",
        "phoneNumber": "03-9876-5432"
      },
      "paymentMethod": "クレジットカード"
    }
    ```

- 期待結果:
    1. HTTPステータスコードが **`400 Bad Request`** であること。
    2. レスポンスボディがJSON形式であり、**`"カートが空か無効です。注文を確定できません。"`** というメッセージを含む `OrderResponse` であること。
    3. DB状態変化: `orders`, `order_details`, `products` テーブルに変化がないこと。
    4. セッション状態変化: セッションの状態に変化がないこと（空のまま）。
    5. OrderController 内で `cartService.getCartFromSession(session)` が呼び出されるが、その結果が空であるため、`orderService.placeOrder` は呼び出されないこと。
    6. **フロントエンドの挙動:** `submitOrderFormAndShowConfirmation` 関数内で `cart.items` が空の場合に `alert('カートに商品がありません。商品を追加してから注文してください。')` が表示され、APIリクエストは送信されないこと。

# 機能：注文機能

## テスト対象API
- POST /api/orders
- POST /api/cart/items

## テストデータ準備方針：
- テストの独立性を保つため、各テストケース実行前にデータベースをクリーンな状態にし、テストケースごとに必要な商品データおよび会員データを投入することを想定します。
- 以下では、テストデータとして投入される商品情報を Product(ID, Name, Price, Desc, Stock, Image_Url, Is_Recommended) の形式で、会員情報を Customer(ID, Name, Email, Password) の形式で記述します。

## テストシナリオ
### No. 3-14
- テストケース名: 会員が在庫数ぴったりの数量の商品を注文する
- 前提条件:
    - テスト商品として以下の商品がDBに登録されていること:
      - Product(ID_OF_AROMA_DIFFUSER, "アロマディフューザー（ウッド）", 4200, "天然木を使用したシンプルなデザインのアロマディフューザー。LEDライト付き。", 15, "/images/aroma-diffuser.png", true)
    - テスト会員として以下の会員がDBに登録されていること:
      - Customer(1, "テスト会員A", "test-member-a@example.com", "password123")
- 手順:
1.	会員ID: 1 の会員としてログインし、セッションを開始します。
  - HTTPリクエスト: POST /api/login （または適切なログインエンドポイント）
  - リクエストボディ例: {"email": "test-member-a@example.com", "password": "password123"}
2.	商品ID: ID_OF_AROMA_DIFFUSER の商品を15点、カートに追加するリクエストを送信します。
    - HTTPリクエスト: POST /api/cart/items
    - リクエストボディ例: {"productId": ID_OF_AROMA_DIFFUSER, "quantity": 15}
3.	HTTP POSTリクエストを /api/orders エンドポイントに送信します。
    - HTTPリクエスト: POST /api/orders
    - リクエストボディ例: {"shippingAddress": "東京都品川区", "paymentMethod": "クレジットカード"} (注文に必要な最低限の情報)

- 入力データ:
    - ログイン時のリクエストボディ: {"email": "test-member-a@example.com", "password": "password123"}
    - カート追加時のリクエストボディ: {"productId": ID_OF_AROMA_DIFFUSER, "quantity": 15}
    - 注文確定時のリクエストボディ: {"shippingAddress": "東京都品川区", "paymentMethod": "クレジットカード"}

- 期待結果:
1.	注文が成功し、注文IDと注文日時を含むJSONが返却される (201 Created)。
    - orderId (注文ID)
    - orderDate (注文日時)
    - shippingFee: 0 (商品合計5000円以上で送料0円を想定 - 4200円 * 15点 = 63000円)
    - totalPrice: 63000
    - grandTotal: 63000
2.	DBに注文情報が登録され、対象商品の在庫が更新されている。
    - Order テーブルに新規レコードが登録され、customer_id が 1 であること。
    - Order_Detail テーブルに、注文された商品（ID: ID_OF_AROMA_DIFFUSER, 数量: 15, 単価: 4200）のレコードが登録されていること。
    - Product テーブルのProduct ID: ID_OF_AROMA_DIFFUSER の在庫が 15 から 0 に減少していること。
3.	セッションからカートがクリアされること。
4.	送料は0円であること。
5.	CustomerId が 1 であること。
