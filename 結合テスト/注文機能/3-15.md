# 機能：注文機能

## テスト対象API

- `POST /api/order`

## テストデータ準備方針：

- テストの独立性を保つため、各テストケース実行前にデータベースをクリーンな状態にし、テストケースごとに必要な商品データを投入することを想定します。
- 以下では、テストデータとして投入される商品情報を `Product(ID, Name, Price, Desc, Stock, ImageUrl, IsRecommended)` の形式で記述します。

## テストシナリオ

### No. 3-15

- テストケース名: 注文（異常系 - 注文処理中に在庫不足が発生）
- 前提条件:
    - **DBにテスト商品として以下の商品が登録されていること:**
        - `Product(1	2025-07-24 14:55:42.687767	机の上をすっきり整理できる木製オーガナイザー。ペン、メモ、スマートフォンなどを収納できます。	/images/desk-organizer.png	TRUE	シンプルデスクオーガナイザー	3500.00	2	1)`
        - **注: 在庫数が2点と少ない商品を想定**
    - セッションに以下のカート情報が存在すること:
        - `Cart(items={"1": CartItem(productId=1, quantity=3, subtotal=17400)}, totalQuantity=3, totalPrice=17400)` （商品ID:1 を3点注文）
    - フロントエンドのフォームは適切に記入されており、バリデーションを通過する状態であること。

- 手順:
    1. フロントエンドで注文フォームに顧客情報と決済方法を入力する。
        - **入力例**: 名前: "顧客 太郎", メール: "taro@test.com", 住所: "東京都新宿区テスト1-2", 電話番号: "0123456789", 決済方法: "銀行振込"
    2. 「注文内容を確認する」ボタン（`#submit-order-form-and-show-confirmation`）をクリックする。
    3. フロントエンドで顧客情報と決済方法のバリデーションが成功し、`currentOrderData` に情報が格納される。
    4. カート情報の取得API (`GET /cart`) が呼び出され、カート内容が `currentOrderData.items` に格納される。
    5. 注文確認モーダルが表示される。
    6. 「注文を確定する」ボタン（`#final-confirm-order-btn`）をクリックする。
    7. HTTP POSTリクエストを `/api/orders/confirm` エンドポイントに送信する。
        - **HTTPリクエスト**: `POST /api/orders/confirm`
        - **リクエストボディ**: `currentOrderData` の内容（顧客情報、決済方法、カートアイテム、合計金額など）
        - **セッション**: 上記前提条件のカート情報
    8. -> OrderController
    9. OrderControllerがCartService.getCartFromSession(session)を呼び出す。
    10. CartServiceがセッションからカート情報を取得し、OrderControllerに返却する。
    11. OrderControllerがOrderService.placeOrder(カート情報, 注文リクエスト)を呼び出す。
    12. OrderServiceがカート内の各商品についてProductRepository.findByIdを呼び出し、DBから商品情報を検索する。
    13. -> DB (商品情報検索)
    14. DB -> ProductRepository -> OrderService (商品情報を返却)
    15. OrderServiceが在庫確認(`product.getStock() < cartItem.getQuantity()`)を行い、在庫不足(`2 < 3`)を検知し、`IllegalStateException`をスローする。
    16. OrderControllerのtry-catchブロックで`IllegalStateException`を捕捉し、エラーレスポンスを生成する。
    17. HTTPレスポンスを受信する。
    18. フロントエンドでエラーメッセージを表示する（`handleError`関数経由でアラートなど）。

- 入力データ (APIリクエストとして送信されるデータ):
    ```json
    {
  "items": {
    "1": {
      "id": "1",
      "productId": 1,
      "name": "シンプルデスクオーガナイザー",
      "price": 3500.00,
      "imageUrl": "/images/desk-organizer.png",
      "quantity": 3,
      "subtotal": 10500.00
    }
  },
  "totalQuantity": 3,
  "totalPrice": 10500.00,
  "shippingFee": 0,
  "grandTotal": 10500.00
}
    ```

- 期待結果:
    1. HTTPステータスコードが **`409 Conflict`** であること（`OrderService` 内で `IllegalStateException` がスローされ、`OrderController` の`catch (IllegalStateException e)`ブロックで処理されるため）。
    2. レスポンスボディがJSON形式であり、エラーメッセージ **`"申し訳ございません、コットンブランケットの在庫が不足しています。現在の在庫: 2"`** を含む `OrderResponse` であること。
    3. DB状態変化: `orders`, `order_details`, `products` テーブルに変化がないこと（`@Transactional` によりロールバックされる）。
    4. セッション状態変化: セッションの `cart` 属性がクリアされずに残っていること。
    5. `OrderService.placeOrder` が呼び出されるが、在庫確認のループ内で`product.getStock() < cartItem.getQuantity()`の条件に合致し、`IllegalStateException`がスローされること。`OrderRepository.save` や `ProductRepository.decreaseStock` (成功しないため)、`CartService.clearCart` は呼び出されないこと。
    6. **フロントエンドの挙動:**
        * 注文確認モーダルが閉じられ、エラーメッセージのアラートが表示されること（`handleError`関数経由）。
        * カートの内容はクリアされず、注文フォームもリセットされないこと。
